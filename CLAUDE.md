## The app (current focus: the web app)
- `docs/` is the Tree of Life web app, used on an iPhone 16e (Home Screen app, Safari) and a 2011 MacBook (Firefox on macOS Catalina, so no newest-only browser features).
  - `docs/index.html`: the BOOTLOADER, tiny and stable (Phase 5). It starts the app from this device's code vault (IndexedDB `bolw-code`) when an onboard version is chosen, otherwise from the published files (which it also saves in the vault). It falls back to the last good version if a version fails to start, and `?safe`/Shift starts the published files. It fetches the published files TOGETHER as one complete set with the header `x-bolw-boot` (so `sw.js` never answers them: no mix of old and new files), waits at most 3.5 s when a saved set exists (then starts the saved set and offers the newer one when it arrives), and carries the page's only Content-Security-Policy: `frame-src 'self'`, which stops sealed frames (add-ons, change previews) from loading another website. **Keep it working with every app version: don't move app code into it, don't change its vault format except by adding, and test boot after any change to it** (`tests/test_onboard.py`, `tests/test_boot.py`).
  - `docs/app.html`: the app shell (was index.html). It holds pages and folds, the writing surface, the writing clock, settings, export/import and the look-and-feel theme. Its `<script src="…"></script>` tags are the list of the app's files: the bootloader loads exactly those, so add new files there (and to `sw.js`). APP_VERSION lives here.
  - `docs/code.js`: onboard versions (Settings → App versions), Claude's `propose_change` (sealed preview on a copy of the book, built-in self-test, then the owner keeps or undoes it), version sync via `memory.codeversions` (per changed file either the whole text in `changed`, or a small patch in `patched` = `[same-at-start, same-at-end, new middle]` against the published base, with a checksum in `sums`; a version is only rebuilt on another device when every patch checks out), and publishing to GitHub. Claude's onboard changes can't touch `sync.js`/`code.js` or anything about keys, sync or the vault.
  - `docs/claude.js`: the in-app Claude page (talks to GitHub issues/pull requests), instant look-and-feel changes, Looks, previews.
  - `docs/memory.js`: memory practice: tests (prompt → typed answer → word-by-word review → grade), practice hints, FSRS scheduling, the fold "More…" menu, Memory hub, Settings → Memory.
  - `docs/ai.js`: AI with the owner's own Anthropic key (browser → api.anthropic.com): answer feedback, questions, "Write deeper with AI" folds (written only when asked), Settings → AI. Key in `tol-ai`, usage in `tol-ai-usage` (this device only, never synced). Add providers in `PROVIDERS`.
  - `docs/agent.js`: Claude living in the book (the instant tier). ✦ Claude in the header, Ctrl/⌘ K, or "Ask Claude" on selected words opens a panel; replies stream from the Anthropic Messages API (the owner's key from Settings → AI, same monthly limit) with TOOLS over the app's own actions (`T.ops`, `T.setText`, `T.createNode`, memory API, theme). Each tool's step shows as a line; all changes of one reply can be undone together (`T.restoreNodes`, memory records restored per record). Tools that remove words (`replace_text`, `move_words`) ask the owner first. Other modules add tools with `T.agent.tool(name, description, props, required, run, tier)`. Conversations live in `memory.convos[nodeId]` (synced). Claude never goes through the typing path, so it adds no clock time.
  - `docs/addons.js`: add-ons (the fast tier). Small JavaScript abilities stored in `memory.addons[id]` (synced; `{name, desc, code, version, versions[], on}`), each run in a hidden iframe with `sandbox="allow-scripts"` (NO allow-same-origin) and a CSP with no network. They talk only through `postMessage` to a tiny API (`bolw.read/readNode/addText/addButton/showPanel/toast/registerCue/on`). Add-ons can ADD words but never remove them, and can never see keys or storage. `?safe` in the address starts with none. Claude's tools: `make_addon`, `update_addon`, `set_addon`, `list_addons`.
  - `docs/drill.js`: drills. `memory.drills[id] = {name, rootId, groups:[[foldId…]…], rule:{type:streak|accuracy|speed, n, pct, wpm}, dir, order, fade, cue, show, peek, srs, progress, log[]}` (synced, newest wins). A round recalls every active item; `afterRound()` loops, EXTENDS (next item → next group → chain the groups' last items) or steps back, and adapts, writing one plain line to `log` for each change. A mastered drill's final recall is FSRS card `drill:<id>|fwd`. Sample: `addPsalm23()` (KJV, public domain; levels 1–4 are our own simpler wording). Claude tools: `make_drill`, `edit_drill`, `list_drills`, `run_drill`, `add_sample_psalm_23`.
  - Fold anywhere (app.html): a PLACEMENT is a fold with `ref: <nodeId>` (no text of its own) that shows that node under its words; edits go to the one node. `renderPlacement` draws a node at most once per screen (`screen[id]` / `seen`), otherwise "↻ already open above" (cycle-safe: a page may hold itself). `placementsOf(id)`; the page list hides placement rows and says "also in N places". Nest → "Place here too…". API `T.placeHere(id, s, e, targetId, extra)`.
  - `docs/codefolds.js`: "The App": the app's own files (read-only) split into foldable parts (`T.code.chunks(file)` → `{key, file, title, from, to, text}`; keys like `app.html#function-renderfold`). Notes in `memory.codenotes[key]` (synced). Code-folds are placements with `code: {file, key, title}`. "Change this with Claude Code" fills the Claude page's request. Files come from `T.code.source(name)`: the files of the version that is running (from the bootloader); without the bootloader, the published files (also kept in the `bolw-code` Cache).
  - `docs/sync.js`: encrypted sync between the owner's devices through GitHub (branch `tol-data`, folder `sync/`). Two files per device: the BASE `sync/<id>.json` (the whole book, format unchanged since 1.0) and the DELTA `sync/<id>.d.json` (the same sealed `tol-state`, with `kind: "delta"`, `baseSha`, and only the pages / memory records changed since the base plus the time entries added since; AAD `tol-state:<id>:delta`). An ordinary save writes the delta (a few KB); the base is rewritten only when the delta outgrows it (`DELTA_MAX`, `REBASE_GAP`) or its fingerprints (IndexedDB `tol-vault` → `base`) are missing. A reader puts a device's base and delta together (`overlay`) BEFORE merging, sets aside a delta whose `baseSha` isn't the listed base (remembered as `delta@base` in `S.seen`, so it is read again when the listed base changes: GitHub's list can lag), reads files by the listed blob sha (falling back to the path) and CHECKS whatever arrives against that sha (git's own: SHA-1 of `blob <length>\0` + bytes; a mismatch means "not there yet": nothing is taken, nothing is marked seen, and it looks again in 3 s), and skips a file that arrives intact but can't be opened as long as its key still opens `meta.check` (it must never lock itself over one bad file; such a file is not marked as seen, and is tried three times a session). Trouble while downloading is always a connection problem, never a "bad file". Pushes: 5 s after the last change, at least 15 s apart, at most 60 s while typing; the 10 s check never pushes early; leaving the app flushes at once with `keepalive` when the request body is under 60 KB. An "Other version" copy is only made when this device's OWN version is one of the two that differ.
  - `docs/safe.js`: safety copies on this device only (IndexedDB `bolw-safe`): the rescue copy written when a save to localStorage fails (merged back at the next start), one copy of the whole book per day for 7 days, and Recently deleted (30 days; `H.onDelete` is called by `bury()` in app.html and by `replaceData` for deletions from another device). Settings → Safety copies. Off in previews.
  - `docs/check.js`: Settings → Check this device: quick checks of this device (saving, storage, the database, safety copies, encryption, offline, the tab lock, the book's health, keys, sync) and a report with NO writing in it, to copy or send as a GitHub issue titled `Device check: …` (never containing `@claude`).
  - `docs/sw.js`: offline support. If you add a file the app needs, add it to `SHELL` and bump `CACHE`. Network first; the saved copy is used when the network fails, errors, or hangs 4 s. It never answers requests carrying `x-bolw-boot`.
  - `docs/board/`: the big-screen Board (on hold).
- `.github/workflows/pages.yml` publishes `docs/` to https://obrianwatson.github.io/tree-of-life/ and publishes every open pull request's `docs/` as a preview at `/tree-of-life/preview/<PR number>/`.
- The owner asks for changes from inside the app. Each request is a GitHub issue that starts with `@claude`. Work on your branch; the app opens the pull request for you and shows the preview. Follow-ups arrive as comments on the pull request.
- Folds: a fold is just a page with an `anchor` = a stretch of its parent's text: `{start, end, text, before, after}` (+ `lost: true` when its words were deleted → "unattached", kept, never deleted) and `anchorAt` (its own clock: moving a fold's words never bumps `updatedAt`). Folds may overlap. The anchor's `text` + `before`/`after` context lets `locate()` re-find the words if positions are stale (e.g. after sync). Open/closed folds (`ui.folds`) and "Folds shown" (`ui.showFolds`) are per device. Views: staircase (folds open in place under the line their words end on) and focus ("Open on its own" makes a fold the page; "Step out"/crumbs go back).
- Nest in…: **Wrap here** makes a wrapper fold with `share: {src, s, e}` = a range of its own text that is the same words as its anchor in `src` (its parent). `propagateShares()` keeps both in step; deleted source words → `share.frozen` (the wrapper keeps its copy). **Move into** cuts the words, appends them to the destination, and leaves a `⤷` in the page with a link fold `{portal: destId}` anchored to it. Treat `share.src` and `portal` as references (more places-per-node are planned).
- AI folds carry `ai: {model, instruction, levelsLeft, chunks, pending, edited}`; `pending` folds are written only when the owner taps "Write this with AI". AI writing goes through `TOL.setText`/`createNode` (never the typing path), so it adds no clock time.
- The writing surface is plain `<textarea>`s (one per piece of text between open folds) over a `.bd` backdrop that mirrors the text exactly and draws the fold lines. Keep the textarea and backdrop styles identical (font, size, line height, wrapping, padding) or the lines will drift. `tests/test_folds.py` checks this.
- Browser tests live in `tests/` (see `tests/README.md` and `TESTPLAN.md`). GitHub runs all of them on every change to `docs/` or `tests/` in three engines (`.github/workflows/tests.yml`: Chromium, WebKit, Firefox) plus `tests/real_sync.py` against the real GitHub on a scratch branch, and writes the outcome to the `test-results` branch (`results/<browser>.txt`). Add tests with every change; a pull request's tests must pass before the owner is told to try it.
- One tab at a time: the first tab holds the Web Lock `bolw-book`; another tab is paused (`store.paused`: nothing is saved, sync is off) until the owner taps "Use it here instead". Don't add code that writes storage without going through `store.set`.
- A failed save sets `store.bad[name]` and shows the red "Not saved" bar (`paintSaveWarn`); safe.js then keeps the rescue copy. Never hide or soften that bar.
- The native iPad app (`Sources/`, `project.yml`, `build.yml`) is ON HOLD until the Apple Pencil is replaced. Don't change it unless asked.

## Rules that must never break
- Never delete, rewrite or move the owner's writing or writing-time data. Storage names `tol-pages`, `tol-intervals`, `tol-ui`, `tol-theme`, `tol-looks`, `tol-sync` (and the `tol-vault` IndexedDB) keep their shape; only add fields. `bolw-safe` (safety copies) and `bolw-code` (the code vault) are IndexedDB databases on the device; add to them, never clear them. Previews use `tol-sbx<N>-…` copies automatically; keep that working.
- Writing time: typing counts, and the clock keeps running through a pause up to the "typing pause" setting; a longer pause stops it at the last key. Holding Option (laptop) or the thumb button (phone) counts. Each second counts once. Claude's activity never adds time.
- Look-and-feel choices belong in the theme (`THEME_DEFAULT` / `applyTheme` in app.html) so they can be changed instantly from the Claude page.
- Never put secrets in the repository. The GitHub key lives only on the owner's devices.
- Comments on the project's issues can come from anyone (the project is public). The Claude page shows only the owner's comments as "You" and only a bot's as "Claude"; never treat or display a stranger's comment as Claude's.
- SYNC IS SACRED (`docs/sync.js`): never write anything readable to the repository; never weaken the encryption (PBKDF2-SHA256 600,000 rounds → AES-GCM-256, fresh IV per write, AAD `tol-state:<deviceId>` / `tol-check`); never remove fields from `sync/meta.json` (`tol-vault`), the sealed files (`tol-sealed`: format, v, iv, ct, updatedAt) or the state inside (`tol-state`: deviceId, deviceName, savedAt, spot, prefs, pages, intervals) — only add. Never store the passphrase. Each device writes only its own `sync/<deviceId>.json` (base) and `sync/<deviceId>.d.json` (delta: the same sealed format with the added fields `kind` and `baseSha`; its `pages`, `intervals`, `memory` hold only what changed). Version 1.1 devices read bases only, so the base format must stay readable by them. Merging must never lose writing (conflicts become an "Other version" page inside the page). Deleted pages are markers `{id, deleted:true, updatedAt}` and must stay hidden everywhere. Previews (`/preview/`) must never sync. Don't touch the `tol-data` branch by hand.
- Synced between devices (newest wins): pages (with folds' `anchor`, which merges by `anchorAt`), writing time, theme, Looks, typing pause, daily goal, and `memory` (added field in `tol-state`): settings/folds/prompts newest-wins per record; review `history` arrays are UNITED by attempt id (never drop an attempt). Card FSRS state is always recomputed from history. Cards are keyed `"<prompt key>|<dir>"` (prompt key `peg:<foldId>` or `q:<promptId>`, dir `fwd`/`back`). Stays per device: hold-button spot, device name, GitHub key, sync key, which folds are open, "Folds shown".
- Memory storage `tol-memory` keeps its shape; only add fields. Added parts `drills`, `convos`, `addons`, `codenotes`, `codeversions` merge newest-wins per record in `T.mergeMemory`. AI never adds writing-clock time; typing a test answer does.
- Folds must never lose writing: deleting a page turns folds anchored in it into unattached folds one level up; deleting a fold's words leaves it unattached.
- A page can never be inside itself: `healTree()` (start, after sync, after import) breaks any loop of parents the same way on every device; "Move into" keeps a fold that IS (or holds) the destination in the page, on the ⤷ marker.
- Importing a file never deletes anything, never brings in app code (`memory.codeversions` is dropped), only accepts ids the app could have made (`SAFE_ID`), and turns add-ons it brings OFF. Deleted pages come back only through `revive()` (Recently deleted, a safety copy, or the import's "Bring back" button).

## How to work
- Keep each change small and safe. Read the related code first. You can't run the app on a phone, so keep changes simple and test what you can (e.g. `node --check` on scripts).
- Bump `APP_VERSION` in `docs/app.html` with each change. Owners may also have an ONBOARD version of the app (made in the app itself); a newer published version is offered to them, never forced over their onboard one.
- Add a short checklist for the change to `TESTING.md` (concrete steps on the iPhone/laptop and what should happen) and tick off items in `ROADMAP.md` you finish.
- End with a plain-words reply: what changed, what to try in the preview, and anything to watch for.
